# MVP API compat surface (NEWS-43)

While the product UI is Kite (`apps/kite`), **`mvp/server` remains the CFP / xcancel / framing backend**. This document freezes the compat surface so the UI pivot does not silently drop ingest or classify.

Owned brief (public, no login) is documented separately in [OWNED_BRIEF.md](OWNED_BRIEF.md).

## Demo (always)

With `npm run dev` (or `npm run server`):

```bash
curl -s http://127.0.0.1:3001/health
# {"status":"ok","app":"mvp-server"}
```

Session + article JSON:

```bash
curl -s -c /tmp/mvp-cookies -X POST http://127.0.0.1:3001/api/login \
  -H 'Content-Type: application/json' \
  -d "{\"password\":\"$MVP_PASSWORD\"}"

curl -s -b /tmp/mvp-cookies http://127.0.0.1:3001/api/articles
# { "articles": [ ... ], "meta": { ... } }

# Optional: one article by id when the store is non-empty
curl -s -b /tmp/mvp-cookies "http://127.0.0.1:3001/api/articles/<id>"
```

Kite does **not** need to proxy these routes. Hit the API on `:3001` directly (default `PORT`).

Keyword/outlet mute rules (`/api/brief/mutes`) are unchanged by topics, and **mute always wins** over desired topics (enforced by triage, [NEWS-87](https://informedcrew.atlassian.net/browse/NEWS-87)).

Public Kite brief routes under `/api/batches…` are **in addition** to this surface (NEWS-44); they are not a replacement for `/api/articles`. **Topic Brief ([NEWS-88](https://informedcrew.atlassian.net/browse/NEWS-88)):** when the article store is non-empty, Brief **story** content is triage's kept stories grouped by desired topic, minus **global mute** ([NEWS-60](https://informedcrew.atlassian.net/browse/NEWS-60)) and seen stories ([BRIEF.md](BRIEF.md)). There is no review step: Accept / Track / claims no longer decide anything on the default path ([NEWS-91](https://informedcrew.atlassian.net/browse/NEWS-91)). The parked story Accept / Unaccept routes still write `brief-membership.json`, which the topic Brief doesn't read. Manual seeds (**Add story**) are saved as kept triage records under a desired topic and pinned first in that section, with no Accept / Track writes ([NEWS-98](https://informedcrew.atlassian.net/browse/NEWS-98)); seeds saved before NEWS-98 have no topic and stay out of the topic Brief. **Mute is shared:** one `mute-rules.json` store and `/api/brief/mutes` CRUD filter the topic Brief via triage and, for the parked desk, story headline clusters and the claim feeds (`claimMatchesMute`); no per-claimId mute API in v1.

**Parked desk behavior.** The parked Track routes still work and keep their stores (`tracked-stories.json`, `tracked-claims.json`). A refresh no longer syncs tracked stories, so tracked story entries no longer get `pendingUpdate: true` when member count grows ([NEWS-61](https://informedcrew.atlassian.net/browse/NEWS-61)) — they keep whatever state they had. Tracked claim entries still get `pendingUpdate: true` when a manual `POST /api/claims/extract` links new evidence or changes a stance. Kite no longer shows an update badge.

### Topic Brief (NEWS-88 / NEWS-89)

With a non-empty article store, `GET /api/batches/:batchId/categories` returns one category (`categoryId: 'world'`, `categoryName: 'Brief'`, `clusterCount` = visible stories) and `…/categories/:categoryId/stories` returns **every** visible story in Brief order (`limit` is ignored). The response `timestamp` is the last successful refresh's `completedAt` (unix seconds), else now. Each story has `id` = `membership_key` = the kept article id, `short_summary` = the AI summary when ready (else `''`), `articles[]` from up to 8 links (distinct domains), and Informed News fields: `informed_article_id`, `informed_topic_id`, `informed_topic_name`, `informed_more` (beyond the top 3), `informed_outlet_count`, `informed_labels` (`'official'[]`), `informed_summary_status` (`'ok' \| 'missing' \| 'unavailable'`), `informed_full_story_status` (`'missing' \| 'ok' \| 'unavailable' \| 'error'`), and `informed_publisher_domain` (the kept article's `publisherDomain`, lowercased with a leading `www.` stripped; absent when the article has none or it isn't a hostname such as `bbc.co.uk` — Less like this offers the outlet block only when present, [NEWS-90](https://informedcrew.atlassian.net/browse/NEWS-90)). A cached `ok` full story additionally supplies its supported rich fields plus `informed_full_story_updated` when it has a living-update note; unsupported / empty sections and map data are omitted. An empty store still returns the fixture story (category also named `Brief`).

`GET /api/brief/overview` (public) →

```
{ ok: true, fixture: boolean,
  refresh: { last, lastSuccess, nextAt, intervalHours, running },
  notices: string[],
  sections: [{ topicId, name, level: 'core' | 'watch', storyIds, moreIds }],
  quiet: [{ id, name, level }],
  filteredOut: number | null }
```

`last` / `lastSuccess` are `meta.json` → `refresh` runs (or `null`); `nextAt` = `lastSuccess.completedAt` + interval (`null` when auto-refresh is off or nothing has succeeded); `intervalHours` is `null` when off; `running` is true while a refresh runs in this process. `notices` are plain-language status lines (provider down/partial, TypeSafe or Ollama not configured, stories not scored for budget, last refresh failed, `brief-seen.json` / `brief-summaries.json` unreadable). An unreadable seen or summaries file is read as empty (stories and overview still return 200); other store read failures → 500. `fixture: true` (empty store) → empty `sections` / `quiet`. `filteredOut` ([NEWS-90](https://informedcrew.atlassian.net/browse/NEWS-90)) is `meta.json` → `triage.dropped` when a triage run exists and wasn't skipped, else `null`; Kite's refresh bar shows it as the **N filtered out** link to `/filtered`. Kite proxy: `apps/kite/src/routes/api/brief/overview/+server.ts`. Guide: [BRIEF.md](BRIEF.md).

Parked claims response (`/api/batches/:batchId/claims`): `{ ok: true, claims: BriefClaimItem[] }`. Source: `ClaimMembership.acceptedClaimIds` only — not the full claim inbox. Muted accepted claims are **omitted** (membership retained). Sorted `createdAt` desc. Empty → `{ ok: true, claims: [] }` (no fixture claims).

Each `BriefClaimItem` includes: `claimId`, `text`, `claimType`, `status` (code-derived), `createdAt`, `confidence` (max evidence score or `null`), `evidence` counts (`total`, `supports`, `contradicts`, `mentions`, `primary`, `sensor`), `clusterKeys`, up to **8** `linkedHeadlines` (same join shape as `GET /api/claims/radar`), optional `verbiage: { short_summary, talking_points } | null` from `claim-enrichments.json`.

Kite no longer proxies the claim, Radar, accept / track / membership, or review-queue routes (`apps/kite/src/routes/api/claims/**`, `api/radar`, `api/batches/**/claims`, and the matching `api/brief/*` proxies were deleted in [NEWS-91](https://informedcrew.atlassian.net/browse/NEWS-91); the `/api/brief/unaccept` proxy followed in [NEWS-98](https://informedcrew.atlassian.net/browse/NEWS-98)). Kite still proxies `/api/brief/seed`, mutes, seen, overview, `stories/**` (including `stories/:articleId/remove`), topics, and `triage/filtered`.
