### Topology ruling (cookie)

Tailscale Serve connects to `127.0.0.1:3001` on the host. Docker's proxy then connects into the container, so Node's peer is a private bridge address, not `127.0.0.1`. Host networking is forbidden: `index.ts` listens on `0.0.0.0`, and host networking would publish that on every interface.

`sessionCookieShouldBeSecure(req)` is true only when both are true:

- The immediate peer is trusted: loopback (`127.0.0.1`, `::1`, `::ffff:127.0.0.1`) or a non-public address (RFC1918, link-local `169.254.0.0/16`, IPv6 ULA `fc00::/7`). A public address is never trusted.
- The connection is TLS (`socket.encrypted`) or the first comma-separated `X-Forwarded-Proto` token is `https` (case-insensitive).

A public peer sending `X-Forwarded-Proto: https` does not get `Secure`. A trusted peer with no HTTPS signal does not get `Secure`, and login still works. Do not set Express `trust proxy` to `true`.

Cost if the private-peer rule is wrong: another container on `nanobot-mem0` could spoof the header and receive a `Secure` cookie for a session that still required the password. Cost if we trust only literal loopback: the tailnet cookie is never `Secure`, which misses the grill.
